# Changelog

## 0.1.7 (2026-11-18)

- `idc.collections()` and `idc.collection_ids()` work again. Two folders of derived data, `_ask/` and `_thumbnails/`, were added at the root of `s3://scigantic-idc-open` on 2026-11-17, and every release up to 0.1.6 listed each top-level folder as a collection: `collection_ids()` returned 181 ids and `collections()` raised `KeyError: 'collection_id'` on the two that have no build report. Top-level folders whose name starts with `_` or `.` are no longer listed, for both buckets. Functions that take a collection id (`series`, `patients`, `clinical`, `read_sample`, ...) were not affected.

## 0.1.6 (2026-11-17)

- The IDC mirror is at IDC v25 (it was v24). 179 collections, 1,044,191 series, 97.6 TB: three collections are new (`fdg_pet_ct_lesions`, `mri_dir`, `qin_sarcoma`), 66 changed (revised series; 18 with different series counts), and 48 gained clinical tables, so 95 collections have a mirrored clinical table. `idc.freshness()` reports `stale: False` against idc-index 0.13.5. No function changed; counts returned for a changed collection differ from 0.1.5's.
- Sample series are the same wherever the series is unchanged in v25 (154 collections). `tcga_hnsc` and `tcga_stad` have a different slide sample, and 11 others hold the revised version of the same series.
- `ldct_and_projection_data`: the clinical tables are now `..._abdomen_v11`, `..._chest_v11` and `..._head_v11`; the `v9` tables are gone.
- Builders: `builders/idc/build_idc_collection_archives.py` takes `--previous DIR` (keep a sample that is still the same series), does not copy the clinical tables of a collection whose every series is CC BY-NC, and carries a withdrawn collection's record forward.
- Tests and docs carry the v25 numbers; the fixture fetch retries a reset connection.

## 0.1.5 (2026-11-17)

- BREAST-DIAGNOSIS: the collection's 429 image series (MR, MG, CT, PT) are no longer in the IDC buckets, and the TCIA collection page offers only the clinical spreadsheet; the 94 SR series are still readable. The three sample series the mirror held were removed, so `idc.samples("breast_diagnosis")` is empty and `idc.read_sample` has nothing to read. `idc.report("breast_diagnosis")["withdrawn"]` records what was checked and when. `series.parquet` is unchanged, as a record of the collection at IDC v24; `idc.pull_series` on one of its image rows raises `NciError`.
- Clinical tables under CC BY-NC are not mirrored. For `midrc_ricord_1a`, `midrc_ricord_1b`, `midrc_ricord_1c`, `nsclc_radiomics_genomics` and `nsclc_radiomics_interobserver1` the build report listed a clinical table whose file is not in the mirror, so `idc.clinical()` failed with a missing-file error. The reports now list only what is mirrored (`clinical_tables_not_mirrored` names the rest), `idc.clinical_tables()` returns `[]` for the five, and `idc.clinical()` raises a `ValueError` that says how to read the table from IDC with idc-index. `idc.collections()["clinical_tables"]` is 0 for them: 54 collections have a mirrored clinical table, not 59.
- `idc.sample_files(c)` returns `[]` for a collection without samples; it raised `FileNotFoundError`.
- Tests: `tests/test_idc_no_mirror.py` runs without the mirror fixture; the fixture manifest carries the current object sizes.

## 0.1.3 (2026-10-09)

- idc-index bridge. New optional extra, `pip install "scigantic-nci[idc]"`, and new `scigantic_nci.idc` functions on top of [idc-index](https://github.com/ImagingDataCommons/idc-index): `client()` (the shared `IDCClient`), `query(sql)` (SQL over every collection), `series(c, ..., live=True)` (the same 31 columns from the live index, for a newer IDC data version or a collection the mirror lacks), `freshness()` / `mirror_version()` / `live_version()` (the mirror is IDC v24; idc-index 0.13.0 is v25 with 1,044,191 series and 3 collections the mirror lacks), `download(selection, dest, exclude_noncommercial=False, dry_run=False)` (idc-index's parallel s5cmd downloader; `exclude_noncommercial` drops CC BY-NC series first) and `citations(c, format)`. Without the extra, every existing function behaves as before and the new ones raise `NciError` with the install command; the base install is unchanged.
- `series()` gained `live=False` after `root`, so existing positional calls are unaffected.
- README and `docs/idc.md` state the relationship to idc-index: the mirror is built from it, and which job each is for.
- Tests: `tests/test_idc_live.py` runs the bridge against a stand-in client, no network.

## 0.1.2 (2026-09-15)

- Faster catalog. `gdc.projects()` and `idc.collections()` now read their rows from one index file at the bucket root, `s3://scigantic-gdc-open/PROJECTS.parquet` and `s3://scigantic-idc-open/COLLECTIONS.parquet`, which hold exactly those frames, instead of 57 `BUILD_REPORT.json` plus 57 `clinical/cases.parquet` files (GDC) or 176 reports (IDC). The ids still come from listing the bucket, so they are always current; an id the index does not cover (a project added after the index was written, or one read from `$SCIGANTIC_NCI_ROOT` or the notebook mount) is built from its own files, and an absent or unreadable index, or one missing a column, means every row is built that way. A local copy at `$SCIGANTIC_NCI_ROOT/<bucket>/PROJECTS.parquet` or `$SCIGANTIC_NCI_ROOT/PROJECTS.parquet` (likewise `COLLECTIONS.parquet`) is used in place of the bucket's. The index is a file, not a prefix, so 0.1.1 clients, which take the top-level directories of the bucket as ids, do not see it. Results are still cached per process.
- The GDC fallback builds rows 16 at a time, as `idc.collections()` already did. Cold from S3 on one connection on 2026-09-15, before any index was uploaded: `gdc.projects()` took 25.6 to 31.7 s in 0.1.1 and 2.0 to 2.2 s now; `idc.collections()` 1.8 to 2.1 s in both. With a local copy of the index the calls took 0.17 s and 0.19 s (one bucket listing plus the index read).
- New `scigantic-nci build-index gdc|idc --out PATH`: builds the frame from every build report, ignoring any existing index, writes it as plain parquet (no pandas metadata, `string` columns, so pandas 1.5 through 3 read back the same dtypes) and prints the row count and size. The bucket owners run it after every rebuild and upload the file; until then `projects()` and `collections()` can show a rebuilt project's previous `built_at` and counts. Built on 2026-09-15: PROJECTS.parquet 57 rows, 5,772 bytes; COLLECTIONS.parquet 176 rows, 15,648 bytes.
- `idc.samples(c)` has a `license_short_name` column, taken from each sample's `license` in BUILD_REPORT.json, so mirrored samples can be filtered by license under the same column name as `series.parquet`. The `license` column is unchanged.
- Data change in the IDC bucket (no code change): Scigantic no longer redistributes CC BY-NC series bytes. The 14 CC BY-NC sample series were removed on 2026-09-15; duke_breast_cancer_mri and nsclc_radiomics now sample a CC BY 4.0 SEG series instead, and seven all-CC BY-NC collections (breast_cancer_screening_dbt, midrc_ricord_1a, midrc_ricord_1b, midrc_ricord_1c, nsclc_radiomics_genomics, nsclc_radiomics_interobserver1, phantom_fda) keep their index tables with no sample. The mirror now holds 321 samples in 168 collections (190 CC BY 4.0, 129 CC BY 3.0, 2 NLM terms), each equal to `series.parquet`'s `license_short_name` for that series. Every collection also has a `samples.parquet` listing its samples with that column. The README and `docs/idc.md` describe the eight collections without a sample, and the multi-frame example uses remind's 39-frame ultrasound instead of the removed tomosynthesis sample.
- Test fixtures: `tests/fixtures/fetch_mirror.py` fetches objects whose live size differs from the manifest instead of failing (the bucket owners rebuild objects; the tests then run against what is live), lists objects that are gone and exits non-zero, and `--update-manifest` writes live sizes back. `tests/conftest.py` prefers a populated `tests/fixtures/mirror`, fetched from the live buckets, over the build-time mirrors.
- Data repair in the GDC bucket (no code change): the 82 AscatNGS copy-number columns in CGCI-BLGSP (67) and HCMI-CMDC (15) whose headers were pipe-joined tumor/normal pairs, and the pipe-joined segment aliquot ids (1 in TARGET-AML, 2 in TCGA-KIRC `segments_gatk4_cnv`), are resolved to the tumor aliquot by `tissue_type`. The README, `docs/gdc.md` and the `copy_number_samples` docstring no longer describe that exception: every matrix column is a single tumor aliquot. If the repair rewrites those projects' `BUILD_REPORT.json`, regenerate PROJECTS.parquet after it.
- Tests for the index read, the merge of ids missing from the index, the fallback on a bad index (missing or renamed column, repeated id, not parquet), the bucket-root path through a stand-in S3 filesystem (including that `list_keys` ignores the root file and that a mounted project is never taken from the bucket index), `build-index`, `samples()` licenses for tcga_lihc and nsclc_radiomics, and a `network` test timing `gdc.projects()` from S3 that passes with or without the index. `tests/fixtures/manifest.txt` gains `nsclc_radiomics/series.parquet` (718 objects).

## 0.1.1 (2026-09-14)

- Documentation fix for `copy_number_samples`. The `*_samples.parquet` tables of the paired copy-number workflows (ASCAT2, ASCAT3, AscatNGS) were rebuilt on 2026-09-13 so that `sample_type`, `sample_submitter_id` and `case_submitter_id` describe the matrix column's own aliquot, the tumor member of the pair; the pair itself stays pipe-joined in `aliquot_submitter_id`. The 0.1.0 README, docs and docstring still described the earlier tables, where `sample_type` was the pair's first aliquot (195 of 392 TCGA-BLCA ASCAT3 rows said Blood Derived Normal), and told users to distrust the column. Checked against the mirror: 138 tables in 42 projects, 37,826 rows, no row whose `sample_type` differs from `clinical/aliquots` for the column's aliquot. The 82 AscatNGS columns in CGCI-BLGSP and HCMI-CMDC that are themselves pipe-joined pairs are noted as the remaining exception.
- The test that pinned the old counts now asserts the corrected invariant.
- `gdc.clinical` now takes `case_submitter_id` from the cases table for every row. It used to come from the diagnoses side of the left join, so a case with no primary diagnosis row had `case_submitter_id` NaN although its `case_id` and `submitter_id` were filled (TCGA-OV 21 of 608 rows, TCGA-LUAD 63 of 585, TCGA-BRCA 2 of 1098, TCGA-BLCA 1 of 412, CPTAC-3 24 of 1866; 1,497 rows across the 57 projects). `clinical()` is now one row per case with a non-null, unique `case_submitter_id`; `os_time_days`, `os_event`, `age_at_diagnosis_years` and `stage` are unchanged.
- CI now runs the whole suite. `tests/fixtures/manifest.txt` lists every object the tests read (717 objects, 254 MB); `tests/fixtures/fetch_mirror.py` fetches them from the public buckets into a cached `tests/fixtures/mirror`, and `tests/conftest.py` falls back to that copy. Before this, CI skipped 65 of 66 tests because the fixtures existed only on the machine that built the buckets.
- README: the IDC licensing paragraph now states that CC BY-NC series may not be used commercially and that `license_short_name` is the authoritative per-series license.
- The GDC mirror is complete: the remaining 21 projects finished building later on 2026-09-13, so all 57 open-access projects of GDC Data Release 46.0 are live and `gdc.projects()` returns 57 rows. The README bullet that said 36 of 57 were built is replaced.

## 0.1.0 (2026-09-13)

First release.

- `scigantic_nci.gdc`: per-project GDC tables as pandas DataFrames: `projects`, `report`, `tables`, `readme`, `manifest`, `clinical` (cases joined to the primary diagnosis with `os_time_days`, `os_event`, `age_at_diagnosis_years`, `stage`), the six clinical tables, `expression` and `expression_samples`, `star_qc`, `mutations` and `mutation_frequency`, `copy_number`, `copy_number_workflows`, `copy_number_samples`, `segments`, `mirna`, `mirna_samples`, `mirna_isoforms`, `rppa`, `rppa_samples`, `rppa_antibodies`, `methylation`, `methylation_platforms`, `methylation_samples`, `case_for_barcode`, `fetch_raw`. Gene, probe and sample subsets are pushed down to parquet.
- `scigantic_nci.idc`: per-collection IDC indexes and samples: `collections`, `collection_ids`, `report`, `tables`, `readme`, `series`, `studies`, `patients`, `slides`, `analysis_results`, `clinical_tables`, `clinical`, `clinical_dictionary`, `samples`, `sample_files`, `read_sample` (`Volume` for radiology, `SlideLevels` for slides), `assemble_level`, `pull_series`, `series_size`, `viewer_url`. Reading DICOM needs the `dicom` extra.
- `scigantic_nci._store`: one resolver for an explicit `root`, `$SCIGANTIC_NCI_ROOT`, the notebook mount, or anonymous S3.
- `scigantic-nci` console script: `projects`, `collections`, `tables`, `readme`, `clinical`, `expression`, `mutations`, `mutation-frequency`, `series`, `pull-series`, `sample`, `viewer-url`; CSV to stdout or `--out`.
- Mirrors at this release: 36 GDC projects (GDC Data Release 46.0) and 176 IDC collections (IDC data v24), both built 2026-09-13.
